# Catalog: production components (`src/pro`)

## Projects as data (`src/manifest`): start here for anything a person edits

A film can be a **project**: plain JSON (a manifest) naming registered components with typed settings on tracks. It's what the Caption Studio edits, what agents write, and what the renderer plays.

| Piece | Job |
|---|---|
| `REGISTRY` (`registry.tsx`) | 14 components a project can use: background, image, card, video, title, captions, stats, callout, rings, route, depthReveal, lightLeak, vignette, logo. Each has a zod `props` schema whose fields carry editor controls (`ui()`: label, control kind, range, group), defaults, a default length and a renderer |
| `manifestSchema` / `parseManifest` / `newItem` / `manifestDuration` (`schema.ts`) | The project format (versioned, with a `migrateManifest` hook), validation with readable `path: message` problems, a new item with defaults, and the length |
| `ManifestReel` + `manifestMetadata` (`ManifestReel.tsx`) | Plays any project. Tracks render back to front, items in `<Sequence>`s, then voice and music. Size, fps and length come from the project. A broken project shows its problems instead of crashing |
| `manifest.schema.json`, `components.json` | Generated by `npm run schema`: the format and the component catalogue (defaults and control hints) for tools that don't import the kit |

- **Demos:**
  - `Manifest-Demo`: the 54D O3 sample project, editable in Studio's props panel.
  - `Manifest-AllComponents`: every component from defaults.
  - `Manifest`: renders `--props=<project.json>`, e.g. `projects/54d-o3-sample.json`.
- **Tests:** `npm test` (24 checks).
- **Adding a component:** add an entry with a schema (`ui()` on every field, a default on every field), a renderer and a description, then run `npm run schema` and check it in `Manifest-AllComponents`. Never change the meaning of an existing field; add a new one with a default.
- **Editors must store projects with every default filled in** (`manifestSchema.parse`). Remotion Studio's props panel crashes on a missing string.


Every component here was lifted from a delivered film, re-themed through `KitThemeProvider`, and checked in the
showcase (`Pro-Showcase-Dhunna54D`, `-DhunnaGold`, `-CrownCrest`; 15 segments × 90 frames, segment *n* starts at
frame `n × 90`). Import from the kit root: `import {Heading, Carousel, KitThemeProvider} from 'reel-components-kit'`.

Status: **prod** = shipped in a film; **new** = built for the kit and checked frame-by-frame in the showcase, not yet in a film.

## Shader backdrops

`ShaderBackdrop` is a full-frame WebGL2 fragment shader, frame-driven and coloured from the theme's 3D palette. It replaces `Backdrop` for a scene. Its props are `kind, energy (0..1, default 0.5), speed, seed, res, opacity, colors`.

Demos:
- `Shaders-Dhunna54D`, `-DhunnaGold`, `-CrownCrest`: each kind for 90 frames behind a heading and a card.
- `Shaders-Grid-*`: all six side by side.

| kind | Look | Use behind | Status |
|---|---|---|---|
| `mesh` | Four soft pools of light drifting | Cards and headings; the default | new |
| `silk` | Broad satin folds with a soft sheen | Interiors, "luxury" lines | new |
| `metal` | Liquid chrome in the brand metal ramp; the top third is kept calm for headings | 3D type, logo, hooks (the loudest one; energy ≤ 0.5) | new |
| `aurora` | Broken curtains of light | Openers and hooks | new |
| `rays` | Shafts of light falling from above | Reveals, the brand name | new |
| `contour` | Drifting topographic lines (full resolution) | Location, map and land beats | new |

Use one kind per film section, with a different `seed` per scene so the pattern doesn't repeat. Keep `energy` at 0.3–0.6 under content. No grain: the only noise is a ±0.5/255 dither against banding. Renders need the ANGLE GL renderer, which `remotion.config.ts` sets.

## Transitions

These are frame-driven, with no `@remotion/transitions` dependency. `Scenes` sequences `Scene`s and the `Cut`s between them; each cut overlaps its two scenes by its length and plays its own sound (`sfx` defaults to on). `planScenes(children).total` gives the film length for `durationInFrames`. Demo: `Bundle-Transitions-*`.

| kind | Default length | Sound | Use |
|---|---|---|---|
| `cut` | 0 | — | Footage and presenter; the default |
| `whip` | 8 | whip | Energy between locations; `dir` = the way the picture travels; directional blur follows the motion |
| `push` | 10 | whoosh-hit | Into a detail or a new space (zoom-through) |
| `blur` | 12 | — | Between worlds only, never between two cards |
| `iris` | 16 | gleam | Opening from a point (`origin`) with a light ring |
| `shape` | 20 | ui-animation | Opens through a `MORPH_SHAPES` outline (pin, house…) that grows geometrically; corners fade in at the end |
| `sweep` | 16 | scan | A light bar wipes the next scene on: the big reveal, once per film |
| `slats` | 16 | swish | Seven strips slide in, staggered |
| `flip` | 16 | swish | The frame turns like a card: card ads |

## Depth reveal

`DepthReveal` builds a photo in near → far from its depth map, with a light edge. It walks the depth histogram, so the area grows evenly even when most of the frame is far away. Props: `src, depth, at, dur, out, w, h, left, top, radius`. Demo: `Bundle-Elements-*`, segment 8.

## Fonts, pairs and captions

**Font library** (`src/type/fonts.ts`): 31 OFL families vendored as woff2 under `public/fonts/lib` (re-vendor with `scripts/fonts-vendor.mjs`), plus the brand faces Geist, Archivo and Cinzel. Each family carries its Latin, Devanagari and Gurmukhi subsets with their Unicode ranges, so Hinglish, Hindi and Punjabi lines render in designed fonts. Call `useFonts([...families])` to hold the frame until they load.

**Font pairs** (`src/type/pairs.ts`): 17 `FONT_PAIRS`, each with a lead, hero and label face plus matching Devanagari and Gurmukhi faces, and a `why` line. `faceCss(pair, 'lead' | 'hero' | 'label')` returns the CSS with the Indic fallbacks in the stack. See the `Font-Pairs` specimen.

**Captions** (`src/captions`):

| Piece | Job |
|---|---|
| `CaptionTrack` | Word timings + a style → paged, animated captions over any scene; layouts `line`, `stack` (lead / hero / tail) and `word` |
| `captionStyleSchema` / `CaptionStyle` | The style as plain JSON (zod): pair, layout, words per page, case, size, hero scale, position, colours (theme tokens or CSS), enter / active / hero effects, stroke, shadow, panel, exit |
| `CAPTION_PRESETS` (20) | Grouped by look: brand (Dhunna steel, Dhunna gold, Crown Crest italic), editorial, energy, clean, indic. Each has a note on when to use it |
| `fromVoJson`, `fromAutocaption`, `fromSrt`, `spread` | Word timings from our voice-over JSON, AutoCaption Studio cues or SRT; `spread` gives even timing, with `*word*` marking a hero |

The editor is the `Caption-Editor` composition in Studio. Pick a preset, theme, script (O3–B3 play the real voice-overs) and background, then override any field in the props panel; Save writes the props to `KitRoot.tsx`. To keep a look, copy the `overrides` into a preset in `style.ts`.

Previews:
- `Caption-Gallery-*` plays every preset in turn;
- `Font-Pairs` is the specimen sheet.

Type rules learned:
- Devanagari has no capitals, so hierarchy comes from size and weight.
- Strokes use `paint-order: stroke fill`.
- Gradient-filled words (karaoke, shimmer) get `drop-shadow`, not `text-shadow`, and no stroke.
- A caption panel arrives with its first word.

## Rules agents must keep

- One effect per beat, on the element that matters. Icons only where they mean something, never spammed.
- CTA never over a card: wrap the cards in `MakeRoom`.
- Real assets only: Phosphor icons, project renders, depth maps. No plain line icons, no glassmorphism, no grain or dot textures.
- Never invent facts (prices, phone numbers, RERA, amenities a project doesn't have).
- Render stills and look at them before reporting: `npm run stills -- out/check Pro-Showcase-Dhunna54D:1200` (3–4 frames per call; it puts temp files on disk 2 — the internal drive is full).
